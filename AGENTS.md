# Notes for agents and contributors

Read [PLAN.md](PLAN.md) (the product spec), then [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md),
[docs/CONTRACTS.md](docs/CONTRACTS.md) and your tasks in [docs/TASKS.md](docs/TASKS.md).
Ask before changing scope or architecture.

## Roles and ownership

Work is split by the [Architect Protocol](ARCHITECT.md). Wander has no server, so the protocol's
`backend/ frontend/ infra/` folders map onto the existing directories instead of new ones
(moving them would break the Xcode project, CI and every open branch; see ADR 006).

| Role | Owns | Typical work |
|---|---|---|
| **Architect** (main session) | `docs/`, `PLAN.md`, `AGENTS.md`, `ARCHITECT.md`, `CLAUDE.md`, `README.md` | design, contracts, task briefs, review, merging, integration on the phone |
| **Backender** | `Packages/RouteEngine/`, `Data/`, `App/Wander/Resources/pois-*.json` (generated by `Data/`) | routing engine, walk tracking, POI pipeline, scoring, curation tooling |
| **Frontender** | `App/` except `App/Wander/Resources/` and `App/Config/` | SwiftUI screens, design system (PLAN §10), MapKit services, app state |
| **DevOps** | `.github/`, `scripts/`, `secrets/`, `.sops.yaml`, `App/Config/` | CI, signing and secrets (SOPS/age), build and install tooling, TestFlight/release |

Shared files: `App/Wander.xcodeproj/project.pbxproj` belongs to Frontender, except signing and
build-configuration settings (DevOps). `.gitignore` is DevOps.

Earlier names in history and PRs: Agent A = Backender (engine), Agent B and Agent C = Frontender
(app shell, planning, walking, place details), "data agent" and "PR corrector" = Architect.
From now on, Agent C's slot is DevOps.

### Rules for every role
- Edit only what you own. If you need a change elsewhere, stop and report it to the Architect.
- `docs/` is the Architect's. If a contract is wrong, report it; don't edit it.
- Each task gets its own branch (`<area>/<short-name>`) and worktree, and ends with a pull request into
  `main` (`gh pr create`). The Architect reviews and merges. Don't merge your own PR.
- Before opening a PR: `scripts/test-engine.sh`, the iOS Simulator build, and `scripts/check-secrets.sh`.
- Report back in at most 25 lines: files changed, commands and results, contract deviations, open
  questions, and what you did **not** verify (e.g. "not seen on a device").
- The simulator renders screenshots black on this Mac. Visual checks happen on the user's iPhone: say
  exactly what to look at.

## Repo map

- `App/`: SwiftUI app. `project.pbxproj` is hand-written (objectVersion 77, synced folders), so new
  files under `App/Wander/` are picked up automatically.
- `Packages/RouteEngine/`: Foundation-only routing package, tested with `swift test`.
- `Data/`: Python (stdlib only) POI pipeline; see `Data/README.md`.
- `scripts/`: helper scripts (`test-engine.sh` builds outside the iCloud-synced Desktop).
- `docs/`: architecture, contracts, tasks, ADRs, brand guide, field-test sheet.

## Commit conventions

- One logical change per commit; keep the tree building where practical.
- Subject: `<area>: <imperative summary>` under ~72 chars.
  Areas: `app`, `engine`, `data`, `scripts`, `ci`, `docs`.
  Example: `data: score and curate POIs, export pois-<city>.json`
- Body (optional): why the change was made, anything non-obvious, and the
  milestone or task id it belongs to (e.g. `Milestone 1`, `FE-3`).
- Don't commit caches, build output, or `xcuserdata` (see `.gitignore`).
